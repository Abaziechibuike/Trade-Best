# TRADE BEST 2-Week Sprint Plan

## Sprint Goal
Build the MVP foundation for TRADE BEST: seller sign-up, product listing, catalog browsing, and basic order flow.

## Sprint Duration
- Week 1
- Week 2

---

## Team roles
- Product owner: defines priorities and acceptance criteria
- Frontend developer: builds UI and screens
- Backend developer: handles data and logic
- QA/tester: validates flows and bug checks

---

## Week 1: Foundation and Seller Setup

### Objectives
- Set up the project structure
- Design the product flow
- Complete seller registration and product listing functionality

### Tasks
- [ ] Create project board and task labels
- [ ] Finalize landing page content and branding
- [ ] Build home page and hero section
- [ ] Create seller sign-up page
- [ ] Create seller login screen
- [ ] Build seller dashboard layout
- [ ] Create product form to add title, description, price, image, and category
- [ ] Save product data to local storage or backend
- [ ] Display product list in catalog view

### Acceptance criteria
- Seller can create a profile
- Seller can add at least one product
- Product appears on the marketplace catalog
- Page layout is clear and easy to use

---

## Week 2: Buying Flow and Validation

### Objectives
- Add customer browsing flow
- Confirm basic order process
- Validate user experience and fix issues

### Tasks
- [ ] Build product detail page
- [ ] Add product search and category filter
- [ ] Add order placement form
- [ ] Show order confirmation page/message
- [ ] Create seller order management view
- [ ] Add change order status option
- [ ] Test the full seller-to-buyer workflow
- [ ] Fix bugs and improve UI clarity
- [ ] Prepare demo for stakeholders

### Acceptance criteria
- Buyer can browse products
- Buyer can place an order successfully
- Seller can see incoming orders
- Seller can update order status
- End-to-end flow works without major errors

---

## Sprint Deliverables
- Working landing page
- Seller sign-up flow
- Product listing feature
- Product catalog view
- Basic order placement
- Seller order management view
- Demo-ready MVP

---

## Sprint Risks
- Incomplete product data or unclear categories
- UI flow too complex for first-time sellers
- Limited time for backend integration
- Need for additional testing before demo

## Risk Mitigation
- Keep MVP scope narrow
- Use simple forms and clear UX
- Prioritize the must-have features only
- Test the core flow before adding extras

---

## Definition of Done
The sprint is complete when:
- All planned sprint tasks are completed or clearly documented
- Core seller and buying flows work
- UI is usable on desktop and mobile-friendly
- Testing confirms the MVP works as expected
- Stakeholders can review the demo without confusion
